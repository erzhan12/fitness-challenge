# Feature 0016: LLM-Powered Challenge Creation

## Description

Add a `POST /api/v1/challenges/create-from-prompt` endpoint that accepts natural language text (e.g. "pushups challenge for 30 days starting tomorrow, 2000 reps total") and uses an LLM to parse it into a structured challenge, validate it against the user's exercise types, and save it to the database.

## Relevant Files

| File | Role |
|------|------|
| `app/services/openai_service.py` | Add `parse_challenge_prompt()` — LLM call returning structured JSON |
| `src/api/models.py` | Add `ChallengePromptRequest`, `ChallengePromptParsed` Pydantic models |
| `src/api/services.py` | Add `create_challenge_from_prompt()` — orchestration + validation |
| `src/api/routers/challenges.py` | Add `POST /challenges/create-from-prompt` endpoint |
| `tests/services/test_openai_service.py` | Unit tests for `parse_challenge_prompt()` |
| `tests/api/test_challenges.py` | Endpoint tests for the new route |

## Algorithm

### `parse_challenge_prompt(text, exercise_types, today)` in `openai_service.py`

1. Build a system prompt with:
   - List of available exercise type names + aliases
   - Today's date (for relative date resolution: "tomorrow", "next Monday", etc.)
   - JSON schema to return
2. Call LLM with `response_format={"type": "json_object"}`, `temperature=0`
3. Parse JSON response into a dict with keys:
   - `exercise_type_name` — matched name from available types
   - `start_date` — ISO date string
   - `duration_days` — integer
   - `target_total` — integer or null
   - `daily_target` — integer or null
   - `challenge_name` — string
   - `is_valid` — boolean
   - `error_reason` — string or null
4. Return the parsed dict (caller handles validation)

### `create_challenge_from_prompt(text, user_id)` in `services.py`

1. Fetch user's active exercise types via `exercise_type_repo.get_all(user_id=user_id)`
2. Get today's date
3. Call `parse_challenge_prompt(text, exercise_types, today)`
4. If `is_valid=False`, raise `ValueError` with `error_reason`
5. Look up exercise type by name: `exercise_type_repo.get_by_name(exercise_type_name, user_id=user_id)` — also try alias matching against fetched list
6. If not found, raise `ExerciseTypeNotFoundError` with list of available types
7. Compute dates: `start_date` from parsed value, `end_date = start_date + timedelta(days=duration_days - 1)`
8. Compute missing target field:
   - Only `target_total` provided → `daily_target = ceil(target_total / duration_days)`
   - Only `daily_target` provided → `target_total = daily_target * duration_days` (not stored; computed on read)
   - Both provided → validate: `abs(daily_target - ceil(target_total / duration_days)) <= 1`; use `target_total`-derived `daily_target` as source of truth
   - Neither provided → raise `ValueError`
9. Build `ExerciseChallengeCreate` and delegate to existing `create_challenge(data, user_id)`

### `POST /challenges/create-from-prompt` in `routers/challenges.py`

- Auth: `verify_api_key` + `get_current_user`
- Request: `ChallengePromptRequest { text: str }`
- Response: `ExerciseChallengeOut` (201)
- Error mapping:
  - `ExerciseTypeNotFoundError` → 404 with available types in detail
  - `ValueError` (parse/validation) → 400
  - LLM unavailable → 503

## Pydantic Models

```python
class ChallengePromptRequest(BaseModel):
    text: str  # natural language description

class ChallengePromptParsed(BaseModel):
    exercise_type_name: str
    start_date: dt.date
    duration_days: int
    target_total: Optional[int]
    daily_target: Optional[int]
    challenge_name: str
    is_valid: bool
    error_reason: Optional[str]
```
