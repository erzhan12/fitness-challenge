# 0007: Migrate from Supabase to Django ORM

## Overview

The migration from Supabase to Django ORM is now reflected in the codebase. FastAPI remains the HTTP layer (REST + Telegram), while Django provides ORM, migrations, and the admin UI (mounted at `/admin`). Supabase is retained only for the one-time migration script, but `app/config.py` still expects `SUPABASE_URL`/`SUPABASE_KEY` at runtime.

**Key Constraints / Decisions:**
- Keep `supabase` in `pyproject.toml` for data migration.
- FastAPI continues to handle HTTP routing and Telegram webhook.
- Django ORM handles all database operations plus Django admin.
- Repository pattern abstracts database access with async wrappers (`sync_to_async`).
- Default DB is SQLite (`data/db.sqlite3`); production uses Postgres via `DATABASE_URL`.
- Django setup is executed early (in `app/main.py` and in `src/core/repositories.py` when needed).

| File | Supabase Usage |

### 1.2 Django Configuration

**File: `src/core/settings.py`**

Key points:
- SQLite default at `data/db.sqlite3`
- Postgres when `DATABASE_URL` is provided
- Django contrib apps enabled to support admin
- Static admin assets served at `/admin/static` (FastAPI mounts `staticfiles/`)

```python
import os
from pathlib import Path
import dj_database_url

BASE_DIR = Path(__file__).resolve().parent.parent.parent
DATABASE_URL = os.environ.get("DATABASE_URL")

if DATABASE_URL:
    DATABASES = {"default": dj_database_url.parse(DATABASE_URL, conn_max_age=60)}
else:
    DATABASES = {
        "default": {
            "ENGINE": "django.db.backends.sqlite3",
            "NAME": BASE_DIR / "data" / "db.sqlite3",
        }
    }

INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.staticfiles",
    "django.contrib.sessions",
    "django.contrib.messages",
    "src.core",
]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",
    "django.contrib.messages.middleware.MessageMiddleware",
]

ROOT_URLCONF = "src.core.urls"
STATIC_URL = "/admin/static/"
STATIC_ROOT = BASE_DIR / "staticfiles"

DEFAULT_AUTO_FIELD = "django.db.models.BigAutoField"
USE_TZ = True
TIME_ZONE = os.environ.get("TZ", "Asia/Almaty")

SECRET_KEY = os.environ.get(
    "DJANGO_SECRET_KEY", "django-insecure-fitness-challenge-local-dev-only"
)
DEBUG = os.environ.get("DJANGO_DEBUG", "False").lower() == "true"
ALLOWED_HOSTS = os.environ.get("ALLOWED_HOSTS", "localhost,127.0.0.1").split(",")
CSRF_TRUSTED_ORIGINS = [
    o.strip() for o in os.environ.get("CSRF_TRUSTED_ORIGINS", "").split(",") if o.strip()
]
```

## Phase 3: Service Layer Migration (actual)

### 3.1 Update `src/api/services.py`

- All service functions are `async`
- Uses repository singletons (`exercise_type_repo`, `challenge_repo`, `log_repo`, `user_stats_repo`, `app_settings_repo`)
- `_model_to_dict()` helper for Django model serialization
- Shared business logic used by REST + Telegram (`compute_exercise_stats`, `list_current_active_challenges`)

### 3.2 Function Mapping (examples)

| Function | Repository Method(s) |
|----------|----------------------|
| `list_exercise_types()` | `exercise_type_repo.get_all()` |
| `get_exercise_type(id)` | `exercise_type_repo.get_by_id()` |
| `create_exercise_type(data)` | `exercise_type_repo.create()` |
| `update_exercise_type(id, data)` | `exercise_type_repo.update()` |
| `list_challenges(filters)` | `challenge_repo.get_all()` |
| `get_challenge(id)` | `challenge_repo.get_by_id()` |
| `get_active_challenge_for_type()` | `challenge_repo.get_active_for_type()` |
| `list_current_active_challenges()` | `challenge_repo.get_current_active()` |
| `create_challenge(data)` | `challenge_repo.create()` |
| `update_challenge(id, data)` | `challenge_repo.update()` |
| `list_logs(filters)` | `log_repo.get_all()` |
| `get_log(id)` | `log_repo.get_by_id()` |
| `create_log(data)` | `log_repo.create()` + `user_stats_repo.increment_total()` |
| `delete_log(id)` | `log_repo.delete()` + `user_stats_repo.decrement_total()` + `user_stats_repo.sync_last_logged_date()` |
| `compute_exercise_stats()` | `log_repo.get_cumulative_count()` + `log_repo.get_today_count()` |
| `list_user_stats()` | `user_stats_repo.get_all()` |
| `get_settings()` | `app_settings_repo.get_singleton()` |
| `update_settings()` | `app_settings_repo.update()` |

### 3.3 Async Considerations

Repositories use `sync_to_async`, so API and Telegram flows `await` these calls.

## Phase 4: Application Integration (actual)

### 4.1 FastAPI + Django admin

**File: `app/main.py`**

- Calls `setup_django()` at import-time to initialize ORM and admin.
- Mounts Django admin at `/admin` via `WSGIMiddleware`.
- Mounts admin static files at `/admin/static` (from `staticfiles/`).
- Uses FastAPI lifespan to start the reminder scheduler (env `ENABLE_REMINDER_SCHEDULER`).

### 4.2 Dependencies

**File: `app/dependencies.py`**

- Keeps Supabase client and `get_supabase()` for migration script compatibility.
- Exposes repository getter functions for dependency injection.

### 4.3 Telegram Service

**File: `app/services/workout_service.py`**

- Uses `_ensure_orm()` to call `setup_django()` when invoked outside FastAPI.
- Uses repositories for CRUD + stats.
- Integrates `app_settings_repo` for reminder scheduling and idempotency.

## Phase 6: Data Migration Script (actual)

**File: `scripts/migrate_data.py`**

- Uses `python-dotenv` to load `.env`
- CLI options:
  - `--batch-size` (default `1000`)
  - `--skip-logs`
  - `--no-verify`
- Parses date/datetime fields safely
- Verifies counts against Supabase unless `--no-verify` is provided

Usage:
```bash
uv run python scripts/migrate_data.py --batch-size 2000
```
