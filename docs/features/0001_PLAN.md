# Feature Plan: Show All Exercises in Bot Response

## Description

Currently, when the Telegram bot responds to a user's workout message, it only displays statistics for the exercises that were entered in that message. The user wants the bot to show statistics for ALL exercises (all active exercise types) in every response, not just the ones that were logged in the current message.

## Files to Modify

### `app/services/workout_service.py`

**Function: `process_incoming_message`**

Current behavior (lines 87-196):
- Processes only exercises from `parsed_result.entries` (the exercises entered in the current message)
- Builds `response_parts` list containing stats only for entered exercises
- Each response part shows: emoji, exercise name with "+X" indicator, day number, today's total, cumulative total, progress bar

Required changes:
1. After processing all entries from `parsed_result.entries` (lines 87-189), track which exercise types were updated in a set (e.g., `updated_exercise_ids`)
2. After the entry processing loop, iterate through ALL `exercise_types` (retrieved at line 73) for active challenges
3. For each exercise type:
   - Skip if it was already processed in the entry loop (to avoid duplicates)
   - Get active challenge using `get_active_challenge(etype.id, today_local)` (same logic as lines 95-111)
   - Calculate today's total: query `exercise_logs` table filtered by `exercise_type_id` and `date = today_local.isoformat()`, sum the `count` values
   - Calculate cumulative total: query `exercise_logs` table filtered by `challenge_id` (or NULL if no challenge) and sum `count` values
   - Calculate status using `calculate_status()` function (same logic as line 130)
   - Build response part using the same format as lines 177-189, but:
     - If exercise was updated: show "+X" indicator (where X is the count from the entry)
     - If exercise was not updated: show current stats without "+X" indicator (or show "+0" if no logs today)
   - Append to `response_parts`
4. Keep the witty comment generation logic, but consider generating comments for all exercises or just the updated ones (current behavior uses last comment)

**Algorithm:**

```
1. Process entered exercises (existing loop, lines 87-189)
   - Track updated_exercise_ids = set()
   - For each entry, add etype.id to updated_exercise_ids
   - Store entry.count for each exercise_id in a dict (updated_counts)

2. Build stats for all exercises
   - For each exercise_type in exercise_types:
     - If exercise_type.id in updated_exercise_ids: skip (already processed)
     - Else:
       - Get challenge (same as lines 95-111)
       - Calculate today_total (query exercise_logs for today)
       - Calculate cumulative_total (query exercise_logs for challenge)
       - Calculate status
       - Build response part (without "+X" or with "+0" if no logs today)

3. Assemble final response (existing logic, lines 192-196)
```

**Edge cases to handle:**
- Exercises with no logs yet: show "Today: 0 • Total: 0/target" with empty progress bar
- Exercises with no active challenge: use default values (day_number=1, total_days=30, target_total=1000, daily_target=33) as in lines 98-102
- Exercises that were updated multiple times in one message: ensure "+X" shows the total count added in this message

## Implementation Notes

- The response format should remain consistent: emoji, exercise name, day info, today's total, cumulative total, progress bar
- For exercises not updated in current message, omit the "+X" line or show "+0" if appropriate
- Maintain the existing witty comment logic, but consider whether to show comments for all exercises or just updated ones
- No database schema changes required
- No changes needed to parsing logic (`parse_workout_message`)
- No changes needed to other functions (`get_exercise_types`, `get_active_challenge`, `calculate_status`)
