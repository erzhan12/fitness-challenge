# Feature 0005: Default Challenge Selection via `is_default` Field

## Description

Add an `is_default` (checkbox/boolean) field to the `exercise_challenges` table. When a user has **multiple active challenges** and enters only a number (without specifying an exercise name), the system should log the entry to the challenge marked as `is_default`.

**Current behavior:** 
- 1 active challenge → defaults to that challenge's exercise type
- 2+ active challenges → defaults to "pushups" (hardcoded fallback)

**Desired behavior:**
- 1 active challenge → defaults to that challenge's exercise type (unchanged)
- 2+ active challenges → check for `is_default=True` challenge:
  - If one found → use that challenge's exercise type
  - If multiple found → use the one with the **lowest `challenge_id`** (deterministic tiebreaker)
  - If none found → fallback to "pushups" (existing behavior)

**New logic:**
```python
if len(challenges_data) == 1:
    # Single challenge - use it as default
    single_challenge = challenges_data[0]
    default_etype = next(
        (et for et in exercise_types if et.id == single_challenge["exercise_type_id"]),
        None
    )
    default_exercise_name = default_etype.name if default_etype else "pushups"
elif len(challenges_data) > 1:
    # Multiple challenges - look for is_default=True
    # Sort by challenge id (ascending) to get deterministic result for ties
    default_challenges = [c for c in challenges_data if c.get("is_default", False)]
    if default_challenges:
        # Pick the one with lowest challenge_id
        default_challenge = min(default_challenges, key=lambda c: c["id"])
        default_etype = next(
            (et for et in exercise_types if et.id == default_challenge["exercise_type_id"]),
            None
        )
        default_exercise_name = default_etype.name if default_etype else "pushups"
    else:
        # No is_default set - fallback to pushups
        default_exercise_name = "pushups"
else:
    # No active challenges
    default_exercise_name = "pushups"
```

## Algorithm

### Default Exercise Resolution (when user sends just a number like "25")

1. Fetch all active challenges within current date range
2. Count the challenges:
   - **count == 0:** Use "pushups" (fallback)
   - **count == 1:** Use that single challenge's exercise type
   - **count > 1:** 
     a. Filter challenges where `is_default == True`
     b. If any found: Select the one with **minimum `id`** → use its exercise type
     c. If none found: Use "pushups" (fallback)
3. Pass the determined exercise name to the parser

### Tiebreaker Rationale
Using `min(challenge_id)` ensures:
- Deterministic behavior (always same result)
- Older/primary challenges take precedence
- No user confusion about which challenge is selected

## Edge Cases

| Scenario | `is_default` Values | Default Exercise | Notes |
|----------|---------------------|------------------|-------|
| 1 active challenge (squats) | N/A | squats | Unchanged behavior |
| 2 challenges, none default | both False | pushups | Fallback |
| 2 challenges, one default | squats=True | squats | Uses marked default |
| 2 challenges, both default | pushups(id=1)=True, squats(id=2)=True | pushups | Lower id wins |
| 3 challenges, one default | squats(id=5)=True | squats | Uses the marked one |
| User specifies exercise | N/A | N/A | "25 squats" always logs squats |

## REST API Examples

### Set a challenge as default
```bash
PATCH /api/v1/challenges/5
Content-Type: application/json
Authorization: Bearer <API_KEY>

{
  "is_default": true
}
```

### Create a new default challenge
```bash
POST /api/v1/challenges
Content-Type: application/json
Authorization: Bearer <API_KEY>

{
  "exercise_type_id": 2,
  "start_date": "2026-01-01",
  "end_date": "2026-01-31",
  "target_total": 1000,
  "challenge_name": "January Squats",
  "is_default": true
}
```
