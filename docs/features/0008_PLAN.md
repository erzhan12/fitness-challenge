# Evening reminders (9pm/10pm/11pm) + persistent reminder setting

## Context
The user wants: “Add a reminders if not all challenges are completed. at 9pm 10pm 11 pm. Add some motivating messages based on left challenges info and left repetitions info. to settings add is_reminder_active.”

Clarifications provided:
- “challenge completed” for the day means `today_total >= daily_target`.
- Send **one combined message** per reminder time; at 10pm/11pm only send if something is still incomplete.
- Reminder times are based on `settings.TZ`.
- Messages should go to Telegram.
- `is_reminder_active` should be **persistent + toggleable** (future-proofed for a Users table later).

This plan builds on the existing admin job endpoint `POST /jobs/daily-reminder` in `app/routers/admin.py` which calls `app/services/workout_service.py` `check_daily_reminders()`.

## Reminder computation + message generation
### Determine which challenges are “not completed”
At reminder run time (for “today” in `settings.TZ`):
1. Query active challenges for today: `challenge_repo.get_current_active(today_local)`.
2. For each challenge:
   - Read `daily_target`.
   - Query today’s progress: `log_repo.get_today_count(exercise_type_id, today_local, challenge_id=challenge.id)`.
3. Mark a challenge “completed” if `daily_target is not None` and `today_total >= daily_target`.

Handling for `daily_target is None` (needed because `ExerciseChallenge.daily_target` is nullable):
- Default behavior for reminders: treat it as incomplete only if `today_total == 0` (so users aren’t nagged endlessly when there’s no daily goal to compare against).
- Include this explicitly in implementation so behavior is deterministic.

### Compute “left challenges info” and “left repetitions info”
For incomplete challenges:
- `left_challenges_count = number of incomplete challenges`
- Per challenge `left_reps = max(0, daily_target - today_total)` (only if `daily_target` exists)

### Build one combined Telegram message (with LLM-generated motivation)
Generate a single HTML message (consistent with existing Telegram HTML formatting in `workout_service.get_exercise_stats_and_message()`), containing:
- A header that includes the reminder time (21:00 / 22:00 / 23:00) and a short prompt.
- A bullet/list per incomplete challenge:
  - exercise emoji + display name (via `challenge.exercise_type`)
  - today progress vs daily target
  - “Need X more reps/min to finish today” (unit taken from `exercise_type.unit`, using “min” where relevant)
- A short “motivating message” generated via the LLM using the “left challenges info” + “left repetitions info”.

Implementation approach:
- Add a helper in `app/services/workout_service.py` (or a new `app/services/reminders.py`) that returns:
  - `should_send: bool`
  - `message_html: str`
  - `incomplete_count: int`

LLM integration details:
- Reuse `app/services/openai_service.py` (already contains LLM client + `generate_motivational_response()`).
- Add a new function in `app/services/openai_service.py`, e.g. `generate_reminder_motivation(context: Dict[str, Any]) -> str`, so we can pass:
  - `left_challenges_count`
  - `remaining_total` (sum of per-challenge `left_reps`, unit-aware)
  - a compact list of `{exercise_name, emoji, today_total, daily_target, left_reps}`
  - reminder hour (21/22/23)
- Keep output VERY SHORT (1–2 sentences) and avoid advising unsafe intensity; use the project’s existing playful coach tone.
- Fallback: if the LLM call fails, return a deterministic local message (similar to current `generate_motivational_response()` fallback behavior) so reminders still work offline.

## Triggering at 9pm/10pm/11pm
Because n8n is no longer used, implement an internal scheduler that runs inside the FastAPI process.

### Internal scheduler loop
In `app/main.py` `startup()`:
1. `asyncio.create_task()` a background loop that:
   - Computes “now” in `settings.TZ`.
   - Computes the next scheduled time among 21:00, 22:00, 23:00 (for today or tomorrow).
   - Sleeps until that time.
   - Calls the reminder runner for the corresponding hour.

### Ensure idempotency (avoid duplicates)
Before sending, check `AppSettings.is_reminder_active` and:
- If `hour == 21` and `last_reminder_21_date == today_local`, skip (already sent).
- Same for 22/23.
After sending, update the corresponding `last_reminder_*_date` to `today_local`.

Note on deployments:
- If you ever run multiple worker processes/replicas, each instance would schedule reminders. The above DB “already sent today” checks mitigate duplicates, but they should be implemented atomically (single update/compare) to be safe.

### Keep `/jobs/daily-reminder` for manual triggering
Update `app/services/workout_service.py` so `check_daily_reminders()` becomes a thin wrapper around the new “evening reminder runner” (optionally with an `hour` parameter) and respects `is_reminder_active`.
This keeps existing tests around `/jobs/daily-reminder` relevant while enabling manual triggers.
