# 0017 — Telegram `/challenge` Command (LLM Challenge Creation)

Create a Telegram `/challenge` command that lets any approved user create a new challenge via natural language, reusing the existing LLM parsing from feature 0016.

## User Flow

1. User sends `/challenge`
2. Bot replies: "Describe your challenge in one message, e.g. _100 pushups in 30 days starting tomorrow_" (with 5-minute timeout)
3. User sends a natural language description (e.g. "200 squats in 2 weeks")
4. Bot shows typing indicator, calls LLM to parse the prompt
5. Bot replies with a **preview card** showing parsed details + inline buttons `✅ Confirm` / `❌ Cancel`
6. User taps Confirm → challenge is created, bot sends success message
7. User taps Cancel → bot sends cancellation message, no DB write

Timeout: if user doesn't reply within 5 minutes after step 2, the flow is silently cancelled. If the user sends another `/challenge` while already in the flow, it restarts.

## Technical Changes

### 1. Telegram Models — `app/models.py`

Add models for callback queries and inline keyboards (needed for the first time):

- `TelegramCallbackQuery` — fields: `id`, `from_` (TelegramUser), `message` (TelegramMessage), `data` (str)
- Extend `TelegramUpdate` with optional `callback_query: TelegramCallbackQuery`
- `InlineKeyboardButton` — fields: `text`, `callback_data`
- `InlineKeyboardMarkup` — fields: `inline_keyboard: List[List[InlineKeyboardButton]]`

### 2. Conversation State — `app/services/challenge_flow.py` (new file)

In-memory conversation state manager for the `/challenge` flow.

**State dict**: `dict[int, ChallengeFlowState]` keyed by `telegram_user_id`

```
ChallengeFlowState:
  - step: "awaiting_prompt" | "awaiting_confirm"
  - created_at: float (unix timestamp)
  - chat_id: int
  - parsed_data: Optional[ChallengePromptParsed]  # from src/api/models.py
  - exercise_type: Optional[ExerciseType]
```

**Functions**:
- `start_flow(telegram_user_id, chat_id)` — sets state to `awaiting_prompt`, records timestamp
- `get_flow(telegram_user_id)` → `Optional[ChallengeFlowState]` — returns state if exists and not expired (5 min TTL)
- `clear_flow(telegram_user_id)` — removes state
- `is_expired(state)` → bool — checks if >300 seconds since `created_at`
- `set_awaiting_confirm(telegram_user_id, parsed_data, exercise_type)` — moves to confirm step, resets timer

Rate limiting: track LLM calls per user. Simple dict `dict[int, list[float]]` of timestamps. Check count in last hour < 10 before calling LLM.

### 3. Telegram Client — `app/services/telegram_client.py`

Add two new functions:

- `send_telegram_message_with_keyboard(chat_id, text, reply_markup: dict, parse_mode="HTML")` — sends message with inline keyboard JSON in `reply_markup`
- `answer_callback_query(callback_query_id, text=None)` — calls Telegram `answerCallbackQuery` to dismiss the loading spinner

### 4. Webhook Router — `app/routers/telegram.py`

Extend `telegram_webhook` to handle callback queries:

- After existing message handling, add: if `update.callback_query` is set, extract `callback_query.data`, `callback_query.from_.id`, `callback_query.message.chat.id`, `callback_query.id`
- Dispatch to a new `process_callback_query` function in background task

### 5. Command Handler — `app/services/workout_service.py`

Add `/challenge` to the command routing in `process_incoming_message`:

- **`/challenge` handler**: calls `start_flow(telegram_user_id, chat_id)`, sends the prompt-request message
- **Intercept in message flow**: before workout parsing, check `get_flow(telegram_user_id)`. If state is `awaiting_prompt` and message is NOT a command:
  1. Send typing indicator
  2. Check rate limit → if exceeded, send error, clear flow
  3. Fetch user's exercise types
  4. Call `parse_challenge_prompt(text, exercise_types, today)` from `app/services/openai_service.py`
  5. Validate via `_parse_and_validate_llm_response` and `_resolve_exercise_type` from `src/api/services.py`
  6. If LLM returns `is_valid=False`, send the `error_reason` to user, clear flow
  7. On success, build preview message and send with inline keyboard (`confirm_challenge` / `cancel_challenge` callback data)
  8. Move state to `awaiting_confirm`
  9. Return early (don't process as workout)

Add new function `process_callback_query(callback_query_id, data, telegram_user_id, chat_id)`:

- `data == "confirm_challenge"`:
  1. Get flow state, verify `awaiting_confirm` and not expired
  2. Call `create_challenge_from_prompt` or directly call `create_challenge` with the already-parsed/validated data from state
  3. Send success message with challenge summary
  4. Answer callback query
  5. Clear flow
- `data == "cancel_challenge"`:
  1. Send cancellation message
  2. Answer callback query
  3. Clear flow
- Expired/missing state → answer callback with "Session expired, use /challenge again"

### 6. Preview Message Format

```
📋 <b>New Challenge Preview</b>

🏋️ <b>Exercise:</b> Push-ups
📅 <b>Start:</b> 2026-03-11
📅 <b>End:</b> 2026-04-09
🎯 <b>Total target:</b> 1,000 reps
📊 <b>Daily target:</b> ~34 reps/day
📝 <b>Name:</b> 1000 Push-ups Challenge

Ready to create this challenge?
```

Inline buttons: `[✅ Confirm]  [❌ Cancel]`

Callback data: `confirm_challenge` / `cancel_challenge`

### 7. Reuse from Feature 0016

These existing functions from `src/api/services.py` will be reused directly:
- `_fetch_and_convert_exercise_types(user_id)`
- `_parse_and_validate_llm_response(raw)`
- `_resolve_exercise_type(parsed, exercise_types)`
- `_validate_challenge_dates(parsed)`
- `_compute_daily_target(parsed)`
- `_build_challenge_data(parsed, exercise_type, daily_target, user_id)`
- `create_challenge(data)`

The `parse_challenge_prompt()` from `app/services/openai_service.py` is reused as-is.

**Note**: The helper functions in `src/api/services.py` are currently prefixed with `_` (private). They need to either be made public (remove underscore) or a new thin orchestrator function should be added that the Telegram flow can call. Preferred approach: create a `validate_and_prepare_challenge(text, user_id)` public function in `src/api/services.py` that runs parsing + validation + resolution and returns `(ChallengePromptParsed, ExerciseType, daily_target)` without creating the challenge. Then both the API endpoint and Telegram flow call this, followed by `create_challenge()` on confirmation.

## Error Handling

- LLM unavailable → "Sorry, challenge creation is temporarily unavailable. Try again later."
- Exercise type not found → "I couldn't find that exercise type. Your available types are: ..."
- Invalid/unparseable prompt → Show LLM's `error_reason` with suggestion to try again
- Rate limit exceeded → "You've reached the limit of 10 challenge creations per hour."
- Expired flow → "Session expired. Send /challenge to start again."
- Already has active challenge for same exercise → Defer to existing `create_challenge` validation
