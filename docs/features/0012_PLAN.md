# Feature 0012: Habit Reward Integration — Bug Fixes, Per-User Config, REST API Trigger

## Description

The Habit Reward integration (`app/services/habit_reward_client.py`) has 3 bugs in its HTTP request (wrong URL path, wrong auth header, wrong payload field). Additionally, `HABIT_REWARD_API_KEY` and `HABIT_REWARD_HABIT_ID` need to move from environment variables to per-user fields on the `UserSettings` model. Finally, the REST API `POST /api/v1/logs` endpoint needs to trigger the habit reward check (currently only the Telegram bot flow does).

---

## Phase 1: Data Layer — Per-User Habit Reward Fields

### `src/core/models.py` — `UserSettings` model (line 47)

Add two new fields:

- `habit_reward_api_key`: `CharField(max_length=255, blank=True, default="")` — per-user API key
- `habit_reward_habit_id`: `IntegerField(null=True, blank=True)` — per-user habit ID

Also add `last_habit_reward_sent_date`: `DateField(null=True, blank=True)` to `UserSettings` — moves idempotency tracking from `AppSettings` (singleton) to per-user. This replaces `AppSettings.last_habit_reward_sent_date` (line 225).

### `src/core/migrations/0007_*.py` (Create)

New migration:
- Add `habit_reward_api_key`, `habit_reward_habit_id`, and `last_habit_reward_sent_date` fields to `user_settings` table

### `src/core/repositories.py` — `UserSettingsRepository` (line 159)

Add two new methods (following existing `try_mark_hour_sent` atomic pattern at line 218):

- `check_habit_reward_sent(user_id, target_date)` — returns True if `last_habit_reward_sent_date == target_date` for the given user
- `mark_habit_reward_sent(user_id, target_date)` — sets `last_habit_reward_sent_date = target_date` for the given user

These replace the same-named methods on `AppSettingsRepository` (lines 853-880), which currently use the singleton `AppSettings`.

### `app/config.py` — `Settings` class (line 5)

Remove:
- `HABIT_REWARD_API_KEY` (line 34)
- `HABIT_REWARD_HABIT_ID` (line 35)

Keep:
- `HABIT_REWARD_BASE_URL` (line 36) — shared across all users

### `.env.example` (line 33-38)

Remove `HABIT_REWARD_API_KEY` and `HABIT_REWARD_HABIT_ID` lines. Keep `HABIT_REWARD_BASE_URL`.

## Phase 2A: Service Layer — Bug Fixes + Per-User Refactor

### `app/services/habit_reward_client.py` (entire file)

**Bug 1 (line 39):** URL path `/api/v1/` -> `/v1/`
**Bug 2 (lines 41-44):** Header `Authorization: Bearer {api_key}` -> `X-API-Key: {api_key}`
**Bug 3 (lines 47-48):** Payload field `date` -> `target_date`

**Refactor `send_habit_completion()`:**
- Change signature from `(completion_date)` to `(user_id, completion_date)`
- Remove reads from `settings.HABIT_REWARD_API_KEY` / `settings.HABIT_REWARD_HABIT_ID`
- Instead, fetch `UserSettings` via `user_settings_repo.get_by_user_id(user_id)` and read `habit_reward_api_key` / `habit_reward_habit_id` from that record
- Keep `settings.HABIT_REWARD_BASE_URL` from env config

**Refactor `is_habit_reward_configured()`:**
- Remove this function entirely (it checks env vars which no longer exist)
- Configuration check is now inline in `send_habit_completion()`: if `api_key` or `habit_id` is empty/null, return False

### `app/services/workout_service.py` — `notify_habit_reward_if_complete()` (line 251)

- Change signature from `(today_local)` to `(today_local, user_id)`
- Remove call to `is_habit_reward_configured()` (line 262) — let `send_habit_completion` handle it
- Replace `app_settings_repo.check_habit_reward_sent(today_local)` (line 266) with `user_settings_repo.check_habit_reward_sent(user_id, today_local)`
- Replace `app_settings_repo.mark_habit_reward_sent(today_local)` (line 276) with `user_settings_repo.mark_habit_reward_sent(user_id, today_local)`
- Pass `user_id` to `send_habit_completion(user_id, today_local)` (line 272)
- Remove import of `is_habit_reward_configured` (line 20)

### `app/services/workout_service.py` — call site (line 1151)

The existing call `await notify_habit_reward_if_complete(today_local)` needs `user_id` added. The `user_id` (AppUser.id) is already available in `process_incoming_message()` — it's resolved from `telegram_user_id` via `app_user_repo.get_or_create_by_telegram_user_id()` earlier in the function. Pass `user_id=user.id` (or equivalent local variable).
