# Feature 0013: Evening Reminder Based on Cumulative Catch-Up

## Description

Change the evening reminder system (21:00, 22:00, 23:00) to use **cumulative catch-up logic** instead of daily target checks. Currently, reminders fire when `today_total < daily_target`. The new behavior:

- **Send** the reminder only for challenges where `cumulative_total < expected_progress` (user has NOT caught up)
- **Silent** (no message at all) when all challenges are caught up
- **Per-challenge**: only list challenges that are behind cumulative progress, not all-or-nothing
- Does NOT affect Habit Reward logic (only evening Telegram reminders)

"No matter how much I did today" — the check is purely cumulative, not based on today's activity.

## Files to Change

### 1. `app/services/workout_service.py` — `compute_evening_reminder()` (line ~1296)

**Current logic (lines 1320-1338):**
- Calls `log_repo.get_today_counts_by_challenge_ids()` to get today's totals
- Checks `today_total < daily_target` (or `today_total == 0` if no daily target)

**New logic:**
- Replace `get_today_counts_by_challenge_ids` with `log_repo.get_cumulative_counts_by_challenge_ids(challenge_ids, today_local)`
- For each challenge, compute `expected_progress` using `calculate_expected_progress(target_total, day_number, total_days, daily_target)`
- A challenge is "incomplete" when `cumulative_total < expected_progress`
- Compute `deficit = expected_progress - cumulative_total` (ceiling to int) as the "need X more to catch up" value

**Algorithm per challenge:**
1. Parse `start_date`, `end_date` from challenge
2. `total_days = (end_date - start_date).days + 1`
3. `day_number = max(1, min((today_local - start_date).days + 1, total_days))`
4. `expected = calculate_expected_progress(target_total, day_number, total_days, daily_target)`
5. `cumulative = cumulative_counts.get(challenge_id, 0)`
6. If `cumulative < expected` → challenge is incomplete, `deficit = ceil(expected - cumulative)`

**Message format change:**
- Replace `today_total/daily_target` display with cumulative deficit display
- e.g., `• 💪 Push-ups: 400/500 expected (need 100 more to catch up)`
- Challenges without a deficit are omitted from the message

This reuses the same pattern already in `_check_all_challenges_complete()` (line ~189) which does the same cumulative check. The difference is `compute_evening_reminder` needs per-challenge detail (deficit amounts) for the message, not just a boolean.

### 2. `tests/services/test_reminders.py` — Update tests

Update `TestComputeEveningReminder` tests to mock `get_cumulative_counts_by_challenge_ids` instead of `get_today_counts_by_challenge_ids`, and verify:
- Challenge with `cumulative_total >= expected_progress` is excluded from reminder
- Challenge with `cumulative_total < expected_progress` is included with correct deficit
- All caught up → returns `(False, None, 0)` (silent)
- Mixed: some caught up, some behind → only behind challenges in message

## Files NOT Changed

- `app/services/habit_reward_client.py` — Habit Reward logic stays as-is
- `app/services/reminder_scheduler.py` — Scheduling logic unchanged (still fires at 21/22/23)
- `send_evening_reminder()` — Wrapper logic unchanged (settings check, idempotency, Telegram send)
- `src/api/` — No REST API changes needed
