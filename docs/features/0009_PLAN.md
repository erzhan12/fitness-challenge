# Feature 0009: Visual Completion Indicators for Challenges and Days

## Overview

Add visual green indicators to mark completed challenges and fully completed days in the fitness challenge application.

**User Requirements:**
- When a challenge is completed for the current day, show a green progress bar (using green blocks 🟩 for completed portions)
- When all challenges for a day are completed, display a green mark indicator on the first line before stats

## Feature Scope

This feature applies to **Telegram bot messages only** (text-based interface). The REST API will receive new fields in response models to support future frontends, but no web/mobile UI implementation is required.

## Technical Details

### 1. Progress Bar Visualization for Individual Challenges

**Current Implementation:**
- `app/services/workout_service.py` - `get_exercise_stats_and_message()` (lines 153-232)
- Uses `format_progress_bar()` function to generate progress bar
- Current format: `[█████░░░░] 49%` (using █ for filled, ░ for empty)

**Required Change:**
- Modify progress bar to use 🟩 (green block) instead of █ when the exercise count meets or exceeds the daily target
- When `today_total >= daily_target` (or challenge is fully complete):
  - Fill completed blocks with 🟩
  - Keep empty blocks as ░
  - Example: `[🟩🟩🟩🟩🟩░░░░░] 50% ✅`

**Algorithm:**
```
1. Calculate completion percentage (progress_percent)
2. Determine filled blocks needed: floor(progress_percent / 10)
3. Determine if daily target is met: today_total >= daily_target
4. If daily target met:
   - Use 🟩 for filled blocks
   - Use ░ for empty blocks
5. If not met:
   - Use █ for filled blocks (current behavior)
   - Use ░ for empty blocks (current behavior)
6. Append ✅ emoji if challenge is completed (optional visual enhancement)
```

**Affected Files:**
- `app/services/workout_service.py` - `format_progress_bar()` function
- `src/api/models.py` - Add `is_daily_complete: bool` field to `ExerciseStatsOut` model
- `src/api/services.py` - `compute_exercise_stats()` function (add logic to determine daily completion)

### 2. Daily Completion Indicator on First Line

**Current Implementation:**
- When user logs exercises, a formatted stats message is sent
- Message includes: day number, progress bar, percentage, status message
- No overall daily completion indicator currently exists

**Required Change:**
- Add a new line at the beginning of the stats message when ALL active challenges for the day are completed
- Format: `✅ Day Complete!` or similar green indicator
- Should appear BEFORE all other stats lines

**Logic:**
```
1. Get all active challenges for today
2. Check each challenge's daily_target (if set)
3. Determine completion status:
   - Challenges WITH daily_target: completed if today_total >= daily_target
   - Challenges WITHOUT daily_target: completed if today_total > 0 (has at least some activity)
4. If ALL challenges are completed:
   - Add "✅ Day Complete!" line at the start of message
5. If some but not all completed:
   - Don't show daily completion line (user sees per-challenge progress)
```

**Affected Files:**
- `app/services/workout_service.py` - `get_exercise_stats_and_message()` function
- `app/services/workout_service.py` - New helper function `is_day_complete()` to check if all active challenges are complete
- `src/api/models.py` - Add `all_daily_challenges_complete: bool` field to stats response (for API consistency)
- `src/api/services.py` - `compute_exercise_stats()` function (add logic for daily completion check)

## Implementation Notes

1. **Daily Target Logic:**
   - If a challenge has `daily_target`, completion means `today_total >= daily_target`
   - If a challenge has NO `daily_target` (is None), completion means `today_total > 0` (has any activity)
   - This aligns with the evening reminder system patterns (see RULES.md)

2. **Backward Compatibility:**
   - Existing API clients will receive new boolean fields but can ignore them
   - Telegram message format changes are additive (new line at top if day is complete)
   - No breaking changes to existing logic

3. **Visual Consistency:**
   - Green block emoji (🟩) clearly indicates completion
   - ✅ emoji reinforces "done" status
   - Should not interfere with existing status messages ("You're doing great", etc.)

4. **Testing Strategy:**
   - Unit tests for `format_progress_bar()` with various completion percentages
   - Unit tests for `is_day_complete()` with different daily_target scenarios
   - Integration tests for message formatting with complete and incomplete challenges
   - Edge cases: No daily_target, 0% progress, 100% progress, multiple challenges with mixed completion

- ✅ API response models include new completion status fields
