# 0014 - Remove `target_total` from DB; derive from `daily_target × total_days`

## Description

`target_total` is redundant — it can always be computed as `daily_target × total_days`. This change makes `daily_target` the single source of truth:

- **Remove** `target_total` column from the `ExerciseChallenge` model
- **Make** `daily_target` a required field (no longer nullable)
- **Compute** `target_total` on-the-fly wherever it's needed (API responses, stats, messages)
- **Migrate** existing data: backfill `daily_target = ceil(target_total / total_days)` for any challenge where `daily_target` is NULL
- **Remove** `target_total` from create/update request bodies entirely (clean break, no backward compat)
- **Keep** `target_total` in API **response** models as a computed field

Formula: `target_total = daily_target × (end_date - start_date + 1)`

## Algorithm: Computing `target_total`

Everywhere `target_total` is needed:

```
total_days = (end_date - start_date).days + 1
target_total = daily_target * total_days
```

## Algorithm: Migration of existing data

```
For each ExerciseChallenge where daily_target IS NULL:
    total_days = (end_date - start_date).days + 1
    daily_target = ceil(target_total / total_days)
```
